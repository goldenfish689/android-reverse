# 请求签名分析

## 定位到真实输入

从目标请求的字段写入点倒推到拦截器、业务方法、Java/native 或应用内脚本。读取 [动态分析](../mobile-reverse/SKILL.md) 采集同一调用的输入与输出；逻辑落在 `.so` 时进入 [native](../android-native/SKILL.md)。

不要凭 `sign` 名称、32 位输出或 Base64 外观断定算法。把处理顺序写成可验证链：字段选择 → 规范化 → 字节编码 → 密钥/摘要操作 → 输出编码 → 写入请求。

## 必须弄清的差异

- 路径是否包含域名、查询串；URL 编码发生在签名前还是后；空格、斜杠、重复参数如何处理。
- 字段排序比较规则、大小写、分隔符、空值与缺失字段、Unicode、数字格式、JSON 顺序和空白。
- 时间戳的单位、nonce 来源、会话/设备字段、body 使用原始字节还是再次序列化。
- 摘要、HMAC、非对称签名或自定义变换；密钥来自配置、会话派生、native 还是 Keystore。
- hex 大小写、Base64 变体、padding、截断或二次摘要。

加密原语和密钥派生细节交给 [android-crypto](../android-crypto/SKILL.md)，保留当前字段与调用链上下文。

## 复现与验收

按 [测试向量约定](../android-crypto/references/test-vectors.md) 保存精确字节。通常至少收集三组覆盖不同输入的样例，另留未参与推导的样例验证。逐段比较规范化文本/字节、原语输入和最终编码，先找第一个不一致的位置。

有随机性或服务端状态时固定/记录相应输入。随机化非对称签名应验签并比较输入规则，不能要求签名字节恒等。缺少密钥、设备绑定或服务端秘密时，说明复现边界，不用硬编码抓到的 sign 冒充算法。

## 输出

给出公式或伪代码、字段清单、调用链证据、最小复现程序的调用方式和验证结果。只有确实运行并通过对照的实现才称“已复现”；服务端接受请求属于另外的验证结果。
