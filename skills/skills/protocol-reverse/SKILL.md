# Android APP 协议还原

输入可为 APK、PCAP、代理导出、请求日志或原始报文字节。先明确对应用户操作、会话和通信方向；仅有 PCAP 时先离线分析，不默认连接目标服务。

## 工作步骤

1. 建立“用户操作 → 线程/函数 → 请求 → 响应”的关联。HTTP 记录方法、路径、查询串、请求头、原始 body、状态码；区分连接头、业务认证字段和请求签名。
2. 判断传输、消息封装、压缩、序列化和加密各层。TLS 密文不能直接按业务协议解码；缺明文时在授权测试环境观察序列化或加密前后的边界。
3. TCP 先做方向划分、重传去重和流重组，再推断帧长、魔数、类型和校验；一个 TCP 包不等于一条业务消息。WebSocket 考虑分片/压缩，gRPC 考虑 HTTP/2 流及消息前缀。
4. 对照多组消息推断字段偏移、长度、端序、变长整数、请求关联 ID 和状态转换。读取 [帧与字段说明](references/framing.md)。高熵只是线索，不能单独证明加密。
5. 用客户端序列化实现验证假设。签名转 [android-signature](../android-signature/SKILL.md)，密文转 [android-crypto](../android-crypto/SKILL.md)，native 编码转 [android-native](../android-native/SKILL.md)。

先制作离线解码器，覆盖完整帧、截断数据、多帧拼接和未知类型。用户需要重放且已有对应范围时，才在测试环境验证；记录 nonce、时间窗、会话状态对复现的影响。

## 输出

交付消息/接口字典（名称、方向、字段、类型、可选性、证据位置）、关键状态转换、原始字节与解码对照、运行命令及已知限制。未知字段保留原始字节和候选解释，不编造业务名称。
