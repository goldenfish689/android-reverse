# 从一个函数恢复控制流

## 平坦化

标记入口、分发器、状态变量、真实基本块和退出块。追踪每个真实块如何更新状态，再还原后继关系；嵌套分发器分别处理。运行轨迹证明某条边出现过，不能证明其他边不存在。

## 虚假分支与 MBA

删除分支前，需要在有效输入约束内证明条件恒定；仅凭一次执行未命中不能删除。简化位运算时保留位宽、符号扩展、溢出和移位规则，必要时以 SMT 或边界样例核对。

处理顺序由依赖决定：先消除阻碍后续求解的已证明谓词/常量，再恢复状态转移，再简化剩余表达式。没有证据时不要套用统一“一键脱混淆”流程。

## 间接跳转与 VM

间接目标从寄存器、跳转表和实际内存值联合推导。仅修改分析器对段的可写属性，不能证明运行时内存不会变化。

VM 分析先恢复虚拟 PC、寄存器/栈、取指、译码和 handler；用受控输入观察单条指令的状态差分，形成 opcode 表，再组合目标函数语义。VM dispatcher 与普通平坦化相似，但恢复方法不同。

## 记录与验证

保留原函数哈希、架构、地址基准、CFG、规则/脚本版本、每次改动与证据。比较输出、内存副作用、异常和外部调用。只有覆盖的输入域得到验证时，才声明该范围内等价；未覆盖路径明确列出。
