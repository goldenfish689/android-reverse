# Android 分析总入口

先从用户要回答的问题出发，只加载当前阶段需要的专项技能。接续已有任务时复用样本信息、授权和已验证结论。

## 开始分析

确认样本位置与 SHA-256、包名和版本（能读取时）、目标功能、现有代码/流量/设备材料，以及输出目录。可离线推进时先做，不为可选信息阻塞。测试设备操作和网络交互沿用用户给定范围，历史案例不构成当前目标授权。

查验工具实际可用性；没有某个工具时使用已有导出物或可用替代工具，并说明限制。不要声称本机已经安装原项目作者的工具，也不要猜 MCP 名称和参数。

## 选择工作路径

| 当前问题或证据 | 下一步读取 |
|---|---|
| 首次拿到 APK，入口不清楚 | [APK 分析](../apk-reverse/SKILL.md) |
| 需要确认函数运行时输入输出 | [动态分析](../mobile-reverse/SKILL.md) |
| 请求字段、帧边界、序列化不清楚 | [协议分析](../protocol-reverse/SKILL.md) |
| sign、X-Sign 或验签不一致 | [请求签名](../android-signature/SKILL.md) |
| Cipher/Mac、密文格式或密钥派生 | [加密分析](../android-crypto/SKILL.md) |
| native 方法或核心 `.so` | [JNI/native](../android-native/SKILL.md) |
| 壳入口、混淆控制流、DEX 动态加载 | [去混淆与加固](../android-deobfuscation/SKILL.md) |

常见路线：APK 定位网络调用 → 协议界定字段 → 签名追踪 → 加密/native 分析 → 动态采样 → 离线比对。只执行与目标有关的环节；证据不足时记录候选解释和能区分它们的下一项实验。

## 交付标准

使用 [报告模板](assets/report-template.md) 记录结果。每个结论附类/方法/文件偏移或日志位置；区分静态推断、动态观察、已复现和未确认。保存命令、工具版本、样本哈希、输入输出样例及失败原因。

可运行产物必须注明调用方式和已测试范围。修改 APK、方法行为或设备设置时记录变化及恢复办法。无法完成的步骤说清楚缺什么，不把“找到了疑似算法”写成“已破解”。
