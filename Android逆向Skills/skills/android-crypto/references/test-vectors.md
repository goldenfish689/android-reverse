# 测试向量约定

每组样例保存来源、目标方法、输入字节、动态参数、期望结果和实际比对。二进制用 hex/base64；原始字节与用于阅读的文本分开，避免换行、转义和 Unicode 归一化改变数据。

建议保存 JSON 数组，每条包含：

| 字段 | 内容 |
|---|---|
| id | 唯一样例编号 |
| source | 日志文件及行号、方法或采样序号 |
| input_hex | 实际送入目标函数的原始字节 |
| parameters | 编码、IV/nonce、AAD、模式及其他动态参数 |
| expected_hex | 来自 APP 或独立可信实现的结果 |
| comparison | byte-equality、decrypt 或 verify |
| result | 本地运行结果与第一处差异 |

签名规范化在原语之前时，额外保留原请求和 canonical_input_hex；key 只在受控本地向量中存放，对外仅写来源或引用。

例：空字节串的 SHA-256 摘要为
`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`。
这只能验证摘要工具工作正常，不能证明目标 APP 使用 SHA-256。

固定 IV/nonce 仅用于重现已有测试样例，不作为生产加密方式。随机化签名验证数学有效性；同一输入不一定输出相同签名字节。
